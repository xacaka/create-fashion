# Create Fashion — Render + Genlook + accounts

HTML-приложение с Node.js backend, регистрацией/входом пользователей и интеграцией Genlook Try-On API.

## Структура проекта

```text
create-fashion-render/
├── public/
│   └── index.html
├── server.mjs
├── package.json
├── render.yaml
├── .env.example
├── .gitignore
└── README.md
```

## Как устроены аккаунты

- У сайта Create Fashion отдельные аккаунты: регистрация по email и паролю, вход и выход.
- Пароли не хранятся в открытом виде: используется scrypt с отдельной случайной солью.
- Сессия хранится в HttpOnly cookie; её хеш хранится в PostgreSQL.
- Пользователь может запускать до 3 примерок в сутки. Ограничение применяется на аккаунт; дополнительно действует ограничение частоты запросов по IP.
- Результат генерации доступен только тому аккаунту, который его запустил.
- Аккаунт сайта не является аккаунтом Genlook. Пользователям не требуется API-ключ Genlook.
- В этой версии email не подтверждается письмом и нет восстановления пароля. Для публичного запуска желательно добавить подтверждение email, восстановление доступа и антибот-защиту.

## Хранение данных

Для пользователей и сессий требуется PostgreSQL. Не храните аккаунты в JSON-файле: файловая система бесплатного Render эфемерная и может очищаться при перезапусках/деплоях.

Бесплатная PostgreSQL база Render действует 30 дней, после чего её нужно перевести на платный тариф в период доступности или данные будут удалены. Для постоянного сайта выберите подходящий постоянный тариф базы и настройте резервное копирование.

## Запуск локально

Требуется Node.js 20 или новее и доступная PostgreSQL база.

1. Скопируйте `.env.example` в `.env`.
2. Заполните `DATABASE_URL` и `GENLOOK_API_KEY` в локальном `.env`.
3. Выполните:

```bash
npm install
npm start
```

4. Откройте http://localhost:3000.

Не добавляйте `.env` в ZIP или GitHub. `.gitignore` уже исключает его.

## Развёртывание на Render

### 1. Создайте PostgreSQL

1. В Render Dashboard выберите **New → PostgreSQL**.
2. Создайте базу в том же регионе, что и Web Service.
3. Для долгосрочного хранения пользователей выберите тариф, который не удаляется через 30 дней. Free PostgreSQL годится только для короткого теста.
4. После создания откройте страницу базы и скопируйте **Internal Database URL**.

### 2. Создайте Web Service

1. Загрузите содержимое ZIP в GitHub-репозиторий. В корне репозитория должны лежать `package.json`, `server.mjs` и папка `public`.
2. В Render выберите **New → Web Service** и подключите репозиторий.
3. Runtime: Node.
4. Build Command: `npm install`.
5. Start Command: `npm start`.
6. Health Check Path: `/api/health`.

### 3. Добавьте переменные окружения

В странице Web Service откройте **Environment → Add Environment Variable** и добавьте:

| Key | Value |
|---|---|
| `DATABASE_URL` | Internal Database URL из созданной Render PostgreSQL |
| `GENLOOK_API_KEY` | секретный API-ключ из аккаунта Genlook |
| `NODE_ENV` | `production` |

После сохранения Render перезапустит/переразвернёт сервис. Не вставляйте API-ключ в `index.html`, браузерный JavaScript, GitHub или публичный чат.

Если используете Blueprint из `render.yaml`, Render также попросит заполнить секретные значения `DATABASE_URL` и `GENLOOK_API_KEY`.

## Как проверить, что всё подключено

1. Откройте `https://ВАШ-САЙТ.onrender.com/api/health`.
2. Ожидаемый ответ после настройки: `{"ok":true,"genlookConfigured":true,"databaseConfigured":true}`.
3. Откройте главную страницу. Должна появиться форма регистрации/входа.
4. Создайте тестовый аккаунт с email, к которому у вас есть доступ, и паролем от 10 символов. Затем выйдите и войдите снова.
5. Добавьте своё фото и одно изображение вещи, затем нажмите **«Сгенерировать образ»**.
6. Если всё настроено, появится результат Genlook. Проверьте баланс/историю расхода кредитов в кабинете Genlook.

Первая реальная примерка может списать кредит Genlook: комплект из нескольких вещей может стоить дороже одной вещи. Не запускайте много тестов: в приложении установлен лимит 3 запроса в сутки на один аккаунт.

## Genlook

- API-ключ принадлежит владельцу приложения и используется только сервером.
- Genlook списывает кредиты по своим правилам: одна вещь обычно стоит 1 кредит, комплект из 2–4 вещей может стоить 2 кредита; точные условия проверяйте в своём кабинете Genlook. Ошибки генерации Genlook заявляет как возвращаемые.
- Верх и низ можно передавать комплектом. Головные уборы и обувь в текущем интерфейсе запускаются отдельно от других вещей.
- Фото человека загружается в Genlook через API. Фотографии товаров временно доступны Genlook по случайным URL на время обработки; временные копии на сервере удаляются по таймеру.
- Условия хранения фотографий и результатов на стороне Genlook регулируются самим Genlook. Перед публичным запуском добавьте понятное уведомление о передаче фото внешнему AI-сервису и получите согласие пользователя.

## Перед открытой публикацией

- Настройте постоянную PostgreSQL базу и резервное копирование.
- Добавьте подтверждение email, восстановление пароля и антибот-защиту регистрации.
- Установите собственные лимиты и контролируйте расход Genlook-кредитов: все пользователи пока используют API-аккаунт владельца.
- Подготовьте политику конфиденциальности и правила обработки фотографий; проверьте возрастные и правовые требования для аудитории сайта.
- Избранное, стили и настройки хранятся локально в браузере и разделяются по аккаунтам на этом устройстве. Между устройствами они пока не синхронизируются.
